# Stage 5.5: Heston Improvement And Fairness Diagnostics

> Note (expiry-clock fix, 2026-10-12): the numbers in this document predate the expiry-clock fix (time to
> expiry now runs to the 16:00 New York close, not 00:00 UTC). Current numbers are in README.md and
> outputs/; old vs new is in outputs/audit/expiry_clock_sabr_summary.csv.


Stage 5.5 does not try to force Heston to beat SABR. It tests whether the Stage
5 Heston underfit is explained by implementation issues, quadrature sensitivity,
optimizer initialization, global-model rigidity, or parameter-instability
constraints.

## Scope

Stage 5.5 keeps the same saved, deterministic research setup:

- Input universe:
  `outputs/stage4_5_sabr_robustness/recommended_calibration_universe.csv`
- SABR benchmark:
  `outputs/stage5_heston/sabr_recommended_fit_errors.csv`
- No live data downloads.
- No rough volatility, local volatility, neural networks, historical backtests,
  or trading signals.

The stage adds sanity checks and controlled Heston variants only.

## Why Stage 5 Needed This

Stage 5 found that a global Heston calibration underfit the filtered short-dated
SPY smile. The fitted parameters were also suspicious: `theta` was near the
lower bound, the Feller condition was false, and `v0/theta` was mismatched.
SABR also had an easier comparison setup because it was calibrated per expiry
while Heston was global.

Stage 5.5 separates five questions:

- Does the Heston pricing implementation pass basic sanity checks?
- Is the Stage 5 result sensitive to quadrature settings?
- Was the global Heston fit materially initialization-limited?
- Can Feller or regularization penalties improve parameter plausibility?
- Does per-expiry Heston narrow the gap in a fairer comparison to per-expiry
  SABR?

## Black-Scholes Limit Sanity Check

The Heston-to-Black-Scholes diagnostic used `sigma=1e-4`, `v0=theta`, fixed
`kappa=2.0`, and `rho=-0.5` across deterministic forward, strike, maturity, and
variance grids.

| Metric | Value |
|---|---:|
| Max price error | 0.000206014 |
| Median price error | 0.000015885 |
| Max IV error | 0.200910 |
| Median IV error | 0.000006407 |

Interpretation: Heston prices approach Black-Scholes. The large max IV error is
from rows with near-zero extrinsic value where IV inversion is ill-conditioned;
the price errors and median IV errors are small.

## Quadrature Sensitivity

The Stage 5 final parameter set was evaluated at 32, 64, and 96
Gauss-Laguerre nodes. The 96-node result is the reference.

| Nodes | Mean Abs IV Diff Vs 96 | Max Abs IV Diff Vs 96 | Price Failures | IV Failures |
|---:|---:|---:|---:|---:|
| 32 | 0.052438 | 0.262025 | 0 | 0 |
| 64 | 0.011850 | 0.167364 | 0 | 0 |
| 96 | 0.000000 | 0.000000 | 0 | 0 |

Interpretation: the Stage 5 parameter set is materially quadrature-sensitive.
That does not by itself prove an implementation bug because the fitted
parameter set is near-degenerate, but it is a real numerical caution for this
snapshot.

## Improved Multi-Start Global Heston

Stage 5.5 used a documented deterministic subset of the proposed start grid:
12 starts spanning `kappa`, `sigma`, and `rho`. The best attempt by weighted
RMSE was:

| Metric | Stage 5 Global | Multi-Start Global |
|---|---:|---:|
| RMSE IV | 0.117433 | 0.117428 |
| Weighted RMSE IV | 0.127041 | 0.127043 |
| Feller satisfied | false | true |
| Parameter warnings | theta bound, Feller, `v0/theta` | `v0/theta` |

Interpretation: multi-start did not materially improve global Heston fit by
weighted RMSE. It found a Feller-satisfying point with nearly identical fit, so
Stage 5 was not simply a bad-initialization story.

## Feller-Penalized Heston

Soft Feller penalties were tested with lambda values `1`, `10`, and `100` using
scaled residuals based on `max(sigma^2 - 2*kappa*theta, 0)`.

| Variant | RMSE IV | Weighted RMSE IV | Feller Satisfied |
|---|---:|---:|---|
| `global_feller_penalty_1` | 0.117489 | 0.127088 | false |
| `global_feller_penalty_10` | 0.117507 | 0.127091 | false |
| `global_feller_penalty_100` | 0.117504 | 0.127128 | false |

Interpretation: the tested soft penalties did not eliminate Feller violations
within the deterministic runtime cap, and fit quality was slightly worse than
the Stage 5 baseline.

## Regularized Heston

The regularized variant adds mild penalties for low `theta`, high `rho`, high
`sigma`, high `kappa`, and large `log(v0/theta)` mismatch.

| Metric | Stage 5 Global | Regularized |
|---|---:|---:|
| RMSE IV | 0.117433 | 0.117887 |
| Weighted RMSE IV | 0.127041 | 0.127687 |
| Feller satisfied | false | true |
| Parameter warnings | theta bound, Feller, `v0/theta` | none |

Interpretation: regularization improved parameter plausibility but worsened fit.
That is a useful stability tradeoff, not a better calibration claim.

## Final Interpretation

Implementation sanity: the Heston pricer passes the Black-Scholes limit price
check and recovers synthetic Heston data generated by its own model.

Numerical stability: the Stage 5 fitted parameter set is materially sensitive
to quadrature node count, so the Stage 5 global result should be treated as a
diagnostic rather than a robust production calibration.

Model flexibility: per-expiry Heston improves over global Heston, which supports
the idea that global-model rigidity contributed to the underfit.

Global versus per-expiry fairness: even after giving Heston the per-expiry
flexibility that SABR already had, SABR still fit the filtered short-dated
snapshot much better.

Parameter plausibility: regularization can produce more plausible Heston
parameters, but the fit worsens slightly. The Feller-penalized variants tested
here did not fully stabilize the Feller condition inside the runtime cap.

Fit quality: no Heston variant beat SABR on this deterministic single-snapshot
universe.

## Limitations

- This is a single saved SPY snapshot, not historical validation.
- Results are diagnostics, not trading signals.
- The per-expiry Heston diagnostic increases flexibility and is not the main
  global Heston model.
- The soft Feller and regularization penalties are intentionally mild and
  deterministic; they are not a production calibration policy.
- Quadrature sensitivity should be revisited before treating Heston outputs as
  deployment-ready.
